# Architectural Design Goals

| Goal ID | Design Goal | Description | Related Requirement | Priority | Justification |
|---|---|---|---|---|---|
| DG-01 | Maintainability (modularity) | Each functional area (directory, requests, ONEAI, announcements, payroll, dashboard) is built as an independent component behind provided interfaces, so a change or a new increment stays inside one component and does not require edits to the others. | NFR-08; Lab 2 Incremental Model (five increments) | High | NFR-08 explicitly requires Directory, Announcements and Payroll to be independently updatable, and the Lab 2 Incremental Model delivers modules in separate increments. Stable interfaces let each increment be added and regression-tested without reopening earlier ones. |
| DG-02 | Security and privacy | Every operation reaches protected data only after authentication, an active-session check (15-minute inactivity timeout) and a role-permission check performed by one access-control component. Payslips are visible only to the owner and authorized Finance/HR; uploads are encrypted at rest. | FR-15; NFR-02, NFR-09, NFR-17 | High | ONE stores salary, personal and policy data. Placing authentication and permission checks in one lower-layer component that every other component must use prevents inconsistent or missing checks. |
| DG-03 | Reliability and availability of external integrations | Failures of the external ERP or Attendance System must not crash ONE: calls time out after 5 seconds, show a clear error, and the Payroll section falls back to authorized cached payslips no older than 24 hours. | NFR-04, NFR-06, NFR-07, NFR-14 | High | ONE depends on systems it does not control (ERP dependency risk, Lab 2). Isolating every external call in an adapter built on the shared IntegrationAdapter contains failures in one place. |
| DG-04 | Performance and scalability | The personalized dashboard loads within 3 seconds, the approvals view within 2 seconds for 50 pending requests, and the system supports 500 concurrent users with no more than 20% slowdown. | NFR-01, NFR-05, NFR-12 | Medium | The dashboard aggregates data from several components, so the architecture must keep these calls short and independent. Medium priority because the semester deliverable is a prototype, but the structure must not prevent scaling later. |
