Feasibility Study
A. Technical Feasibility
ONE is technically feasible as an academic software project because its functionality can be implemented using commonly available web/mobile development technologies, databases, APIs, and AI services. The main technical challenge is integration with the company's ERP and attendance systems. These systems may require authorized APIs or other integration methods. If access to real systems is unavailable, mock APIs and sample data can be used for the prototype.
Assessment: Feasible, with ERP and internal-system integration being the main technical constraint.
B. Economic Feasibility
The project can be developed with limited costs as an academic prototype. The main resources are development computers, development software, a database, hosting or a local environment, AI services if required, ERP/API access, and development and testing time. Existing or free development tools can be used where possible. A full enterprise deployment would require additional costs for hosting, security, AI usage, integration, maintenance, and support.
Assessment: Feasible for an academic prototype; full enterprise deployment would require additional budget.
C. Operational Feasibility
ONE addresses a genuine workplace need by centralizing common employee activities that may otherwise require multiple systems or complex ERP navigation. Employees can use one application for leave, expenses, attendance, IT assets, support, approvals, documents, and company information. ONEAI can further help employees find information in approved company policies and procedures.
Assessment: Operationally feasible because the system addresses common employee and administrative needs.
D. Schedule Feasibility
A complete enterprise version of ONE would be too large to implement within a typical university project period. However, the Incremental Model allows the team to prioritize core features and develop them in stages. The initial prototype should focus on authentication, dashboard, leave, attendance, expenses, approvals, IT assets, and ONEAI, with additional features implemented if time permits.
Assessment: Feasible if the team maintains a clearly defined scope and prioritizes core functionality.
E. Overall Feasibility
ONE appears to be a feasible software project for the course. The main functionality can be implemented using available software-development technologies, and the project addresses a genuine need for a simpler and more centralized employee experience. The biggest constraints are ERP integration, access to company data, security and privacy requirements, ONEAI accuracy, and the limited project schedule. These constraints can be reduced through mock data/APIs, role-based access, approved AI sources, and incremental development.
